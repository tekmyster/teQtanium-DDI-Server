# MISP and typed EDL integration

This implementation is API-configured; no EDL configuration screen is included. Nothing enables itself. MISP evidence stays Monitor. Existing MISP rules, tags, `to_ids`, source modification timestamp and values are not changed upstream. Fetch provenance records the configured source and local UTC fetch time; local expiry is measured from fetch time, not the MISP attribute's modification time.

MISP requires a complete HTTP 200 response without Content-Range. Attribute identity must be a nonzero UUID in hyphenated form; when UUID is absent, a canonical positive unsigned numeric MISP ID is accepted. Invalid/repeated upstream identities or duplicate derived IDs reject the snapshot without silently removing entries. Existing cached IDs remain readable until normal expiry/refresh.

MISP capacity is fixed at 100000 raw attributes and 100000 normalized indicators, 1000 attributes/page with up to 101 pages (including an empty final proof page at the exact boundary), 8 MiB/page, and a 120-second operation deadline. Composite domain/IP attributes count as two normalized indicators. No `to_ids`, tag, or event subset is silently selected. Local policy rules and each EDL input retain their 10000-entry limit. MISP/EDL fetches never run on the resolver query path. The transport header timeout is 120 seconds; the shorter EDL operation deadline remains 60 seconds. Canonical row costs are counted before retaining MISP rows, and cache validation counts without allocating discarded output buffers.

## MISP URL evidence and coverage

HTTP(S) URL attributes retain their full URL and original upstream value/provenance; DNS does not match or enforce their paths. Valid absolute URIs with unsupported schemes, such as `file:`, are retained verbatim as `MispUnsupportedUrl` source evidence in the same bounded cache. They are not fetched, opened, rewritten to HTTP, expanded into DNS host rules, indexed as active device evidence, or included in typed EDL output. Their source type, exact original value, scheme, reason, identity, fetch/modification metadata and original expiry remain attached. This evidence kind cannot be configured as a local policy rule. Malformed HTTP(S), invalid metadata, duplicate identities or exceeded budgets reject the refresh and retain the last complete cache.

A complete selected traversal can therefore have limited supported coverage. `mispHealth.snapshotEntries` counts all retained normalized entries, including unsupported source evidence; `indicators` counts currently unexpired supported entries; `unsupportedAttributes` counts the retained unsupported entries; `dnsMatchingIndicators` counts unexpired DNS-compatible entries; `urlEvidenceOnly` counts unexpired HTTP(S) URL evidence. The readable status reports unsupported schemes/counts, and operations reports `PartialCoverage` after a complete traversal containing unsupported evidence. No unsupported URI is presented as an enforced rule. Unsupported entries consume the same 100000 normalized-entry and 64 MiB canonical budgets as other MISP entries.

`completeSnapshot` records that this process completed the selected traversal, including its final pagination proof. It is not a transactionally frozen upstream database, current-source freshness guarantee, or proof of access from another node. Restart/replication retains the source evidence and counts but requires a local refresh to establish that process's traversal status. A failed refresh does not extend last-good expiry. URLs and unsupported URI evidence remain private unless a separately authorized compatible publication explicitly selects supported entries; unsupported kinds remain excluded even when their IDs are selected.

## Inputs

Security policy accepts `edlFeeds`: up to eight named sources. Each supplies `id` (ASCII letters/digits/hyphens, 64 maximum), `kind` (`Domain`, `Network`, or `Url`), HTTPS `url`, `enabled` (false), `action` (`Monitor` by default; explicit `Block` opt-in), `apiKeyEnvironment` (optional protected node-local `DDI_EDL_*_API_KEY` reference), `authScheme` (`Bearer`, `Basic` encoded credential, or `Raw` Authorization), `refreshSeconds` (60–86400; default 300), and `cacheLifetimeHours` (1–168; default 24). All nodes use their own environment and platform CA/hostname trust; credentials are never replicated in policy/cache. No certificate-validation bypass or automatic trust installation exists. Credential values must contain visible ASCII only, at most 4096 characters, with no whitespace or control characters. Raw sends that safe opaque value unchanged, including padding such as `=`; Basic expects an encoded credential, not a literal username/password pair.

A source returns HTTP 200 `text/plain`, UTF-8, one typed value per line. Blank lines and full-line `#` comments are ignored. Limits: 2 MiB, 20000 physical lines, 10000 unique values, 2048 characters per value, 60 seconds including headers/body per source, one refresh batch per node. Redirects, partial-content responses, wrong MIME type, invalid UTF-8, wildcards, inline comments, mixed kinds and malformed entries reject the complete refresh. Domain names are exact, normalized IDNs. IP hosts and CIDRs become canonical networks. URL scheme, host and path remain URL evidence; DNS cannot enforce URL paths and never broadens them to domains. No per-query outbound fetch occurs.

A complete valid empty response retracts that source. Failure retains the last complete snapshot only until its original expiry, after which it is inactive. Successful refresh persists via flushed temporary file and atomic replacement before publishing the index. Cache restore/restart validates source, type, entries and UTC lifetime; source changes cannot activate a differently bound snapshot. Settings view receives `edlHealth` with last source success/attempt/expiry/state/count. Source authentication failures report a generic failure without secrets. Cache presence is not a fresh connectivity check. MISP has a separate 64 MiB canonical serialized cache budget. EDL keeps a 16 MiB aggregate budget across all eight feeds, including metadata and JSON escaping. The same limit applies before atomic write/visible replacement and to normalized restart/restore/export. Overflow retains the prior complete cache/source snapshot; individual feed limits do not override the aggregate budget.

## Publication

`edlPublications` contains up to 32 named lists: `id`, `kind`, explicit `selected` pairs of `source` and indicator `id`, `enabled` (false), and `intendedAction` (`Monitor` by default). Only explicitly selected active, non-Allow, unscoped threat indicators of that exact kind are published. Selections can reference local indicators, MISP IDs, or `EDL:<feed-id>` indicators. Unscoped local Allow indicators suppress exact values, covered domains and overlapping networks. Client-scoped indicators are excluded because a plain EDL cannot preserve their scope. No events, client queries, DHCP leases, inventory, model output or credentials are traversed by publication.

Stable read endpoint: `GET /api/security/edl/export?list=<id>` over direct HTTPS with an Authorization Bearer session/API token. Direct TLS is captured from the listener connection before SSO forwarded-origin rewriting; `X-Forwarded-Proto: https` on plaintext cannot satisfy it. A TLS-terminating proxy must also use TLS to the service for this endpoint. URL tokens and node proxy selection are rejected. Access requires Settings.View and Administration.View; create a dedicated read-only user/group with those view grants, no modify/delete privileges, and a managed API token at deployment. DNS-only and reader fixtures are rejected. No new credential or permission is automatically provisioned. Outputs are private by default and disabled until explicitly selected/enabled by an administrator. Policy changes to source or publication connections, including rollback, require Settings.Modify and Administration.Modify.

Success is `text/plain; charset=utf-8`, canonical values separated by LF, trailing LF for nonempty lists. Headers: `X-teQtanium-EDL-Kind`, `-Action`, `-State`, `-Generated`, optional `-Expires`; `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`. Unauthorized 401, insufficient permission/plaintext 403, missing or disabled list 404; no ordinary JSON success wrapper. Unavailable/expired/exempt selected values are omitted and state reports this. A valid list with no remaining values is HTTP 200 empty, allowing downstream retraction; downstream outage/stale retention is a consumer setting. `intendedAction` communicates intent only: text subscription consumers independently control enforcement. No firewall subscription, ACL or blocking policy is installed.

Existing EDL Manager owns aggregation/scoring and provider protection decisions. Inspection found authenticated `/lists/<name>.txt` generation outputs, including separate allow/block/review lists. Browser session login does not establish an authorized machine-feed contract. Release must verify exact selected upstream gateway/list, allowed redistribution, kind, authentication, CA chain, source path and downstream behavior. This implementation's 10000-entry limit is smaller than EDL Manager's 50000-entry publication guard. Larger lists must be intentionally partitioned upstream; truncation is rejected. Text formatting alone does not prove Palo Alto or any consumer compatibility.

## Release gates

Local fixtures are synthetic. Separate Monitor input consumption was activated and postchecked; see [dated status](DEPLOYMENT-STATUS.md). This is not blocking/accuracy qualification or output publication. Consumer-specific list selection, redistribution, subscription/expiry and required source/access paths remain separate release gates. The latest cache/local-refresh health repair is accepted locally and undeployed, so the behavior described below must not be assumed to be the currently loaded UI. No previously rejected live security action is retried by this documentation update.

Peer-refresh ordering: an authenticated configuration transfer with consistent UTC source/fetched provenance older than an in-flight local traversal does not invalidate that traversal. A newer or unorderable peer snapshot, explicit administrative restore, or changed source settings (including ABA) still supersedes it. Superseded refreshes report their attempt and reason; they are not successful source refreshes. The final durability boundary and all capacity/deadline limits are unchanged.

## Cache and local fetch health

Dashboard > Protection / MISP and Security show cache usability separately from this process's local source fetch. A matching, unexpired peer cache can be active while the local fetch has never completed, failed, timed out, or become stale. Unsupported URL schemes remain evidence only; they never count as DNS matching or usable supported indicators. Unsupported-only caches are labeled evidence only.

The existing health fields and CompleteSnapshot marker retain their meaning. Peer/manual restore does not fabricate local success or local completeness. New cache fields describe state (Usable, EvidenceOnly, Empty, Expired, SourceChanged, Rejected, Disabled), validated source URL, origin (Local, Peer, Restored, Persisted, None, Rejected), consistent source fetch start if known, node receipt if observed, next active supported expiry, last supported snapshot expiry, and active unsupported count. A restart reports Persisted with original evidence fetch provenance where coherent; it does not invent a peer identity, receipt time, or completed local traversal. Source URL contains no credentials/query/fragment and remains behind Settings view permission.

LocalRefreshState describes the latest local attempt (NeverCompleted, Fetching, Succeeded, Superseded, Failed, TimedOut, Canceled). LastAttempt records its start, LastSuccess retains the existing successful fetch start semantics, LastFailure records the most recent failure, and LocalRefreshStale independently measures last success against twice the configured interval. LocalSuccessSourceMatches identifies whether that successful traversal used the current source. Local history is process-local, including after restore/restart. Cache replication never resets that history. Invalid restore input leaves the previous valid cache intact; invalid persisted input is rejected. Empty successful source results still retract the old cache. Cache health is evidence availability, not proof of enforcement, provider connectivity, or production integration acceptance.

Operations retains existing fields and identifiers; state now describes active cache coverage, while cacheState and localRefreshState expose the independent dimensions. Neither summary forces an overall green result. The cache source may differ from current settings after a source change; the inactive cache's provenance remains visible. Count fields are recomputed from the current in-memory snapshot and actual expiry, without provider requests.
