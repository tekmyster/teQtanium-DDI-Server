# Syslog forwarding

Forwarding is per node and disabled by default. DNS query export is separately opt-in. Existing system/DHCP logging, security-event production, DNS answers, DHCP decisions and license-failure isolation are unchanged. DNS/client/device information can be retained on disk and exported after forwarding is enabled; select categories and a collector with appropriate access and retention controls.

The existing **Settings > Logging > Syslog** screen configures UDP/TCP. Native TLS and replay-age controls in this increment are **API-only**; use the direct node API for a TLS configuration. No console assets changed. Settings view requires Settings view and a direct user/API-token session. Set/test require Settings modify and Administration modify. Cluster service tokens cannot redirect forwarding. Native set rechecks current session validity/rights after waiting for the configuration lock and after stopping the previous worker, then checks again before returning settings. Syslog restore also checks the initiating session at its configuration commit boundary. Already submitted bytes cannot be recalled by a later settings or permission change.

## Transport and trust

Messages use [RFC 5424](https://www.rfc-editor.org/rfc/rfc5424) UTF-8 with the message BOM. Facility defaults to Local 0. Headers retain the original UTC event timestamp, source hostname assertion, application `teQtanium`, process ID and category (`system`, `security`, `dns`, `test`) across replay. The asserted hostname/process in a replayed payload describes its original producer; it is not transport peer authentication. CR/LF/NUL in system text are escaped. Security JSON remains bounded, with reduced valid JSON marked `detailsLimited` when necessary. Records are limited to 8 KiB of complete UTF-8 bytes.

`Transport` accepts `Udp`, `Tcp`, or `Tls`. UDP/TCP are unencrypted. TCP supports `OctetCounting` and `LineDelimited` framing ([RFC 6587](https://www.rfc-editor.org/rfc/rfc6587)). TLS requires octet counting as in [RFC 5425](https://www.rfc-editor.org/rfc/rfc5425), supports TLS 1.2/1.3, and never falls back to plaintext. Supply the collector's actual hostname or IP SAN in `server` and its explicit port (commonly 6514 for TLS; changing transport does not change the configured port).

TLS uses native `SslStream` hostname/IP, validity, server-auth usage and certificate-chain validation. Empty `tlsCaCertificate` uses system trust. Alternatively provision one base64 DER CA certificate (maximum 2800 characters) as a collector-specific custom root; this replaces system roots for this sender and does not change machine trust. Custom chain validation disables certificate downloads. Revocation checking is not implemented by this sender. There is no trust-all callback, validation bypass, client certificate/private-key setting, or pin-only identity shortcut. Certificate changes require an administrator update.

Example API settings (fill in the owned collector and public CA locally; do not include a private key):

```json
{"enabled":true,"server":"collector.example","port":6514,"transport":"Tls","tcpFraming":"OctetCounting","systemEvents":true,"securityEvents":true,"dnsQueries":false,"tlsCaCertificate":"BASE64_DER_CA","maxAgeSeconds":86400}
```

`GET /api/logging/syslog/get` returns settings and health, plus `tlsTrustMode` and the CA SHA-256 fingerprint. CA contents are redacted: `tlsCaCertificate` is `Retain` for an existing custom root and empty for system trust. Submit `Retain` to preserve the node's existing custom CA; it fails if none is provisioned. An empty string explicitly selects system trust. `POST /api/logging/syslog/set` takes the settings JSON and current `revision`. Stale revisions fail. A successful save means configuration was saved; inspect health to detect an unavailable spool or collector. `POST /api/logging/syslog/test` returns `queued: true` only for memory admission. Use bearer authentication.

## Admission, persistence and bounded replay

Producers format a bounded record and try a nonblocking memory admission. They never wait for disk flush, DNS resolution, TLS or socket I/O. **Queued is not durably persisted.** A background writer writes a record to a temporary file, flushes it with `Flush(true)`, and atomically renames it into `syslog-spool`. Only then does an independent sender attempt delivery. A crash can lose records still in memory or in an uncommitted temporary file. Graceful disposal stops network work and drains accepted memory records to disk; slow storage can delay disposal/configuration, while DNS/DHCP producers remain independent.

The shared pending bound is 1024 records across memory, durable backlog and in-flight work. A full pending queue rejects the newest offered record and increments dropped; it does not evict existing accepted records. Memory payloads are at most 8 MiB (excluding transient formatting/serialization allocations). Each committed spool file is at most 16 KiB including its envelope, so committed logical file content is at most 16 MiB, plus one temporary file of at most 16 KiB and the owner lock. Filesystem allocation/metadata overhead is additional. A single-process lock prevents concurrent ownership. The internal ready channel cannot grow beyond reserved pending capacity.

Each envelope records a stable spool ID, original enqueue time, source settings revision, payload digest and a binding to server, port, transport, framing, CA and category selection. Recovered records keep the exact original payload. Retention defaults to 86400 seconds; `maxAgeSeconds` accepts 60 through 604800. Expired/future-dated, corrupt or oversized records are individually discarded and counted. Interrupted temporary files are removed at startup, without discarding valid neighboring committed records. Corrupt/missing configuration disables forwarding and leaves spool contents untouched until valid configuration is explicitly saved. A spool path/storage failure degrades forwarding and reports an actionable error; it does not prevent DNS/DHCP startup.

Socket connect/handshake/write work has a three-second timeout. Failures retain the head record and retry with 1, 2, 4, 8, 16, then at most 32 seconds of backoff. Expiry is checked before each attempt; an outage can therefore delay expiry removal by the current retry interval. Retries are serialized. Disabling forwarding pauses retained records and prevents new admission. Re-enabling the same binding replays eligible records. Changing destination, trust, framing or event selection discards and counts old-bound work rather than redirecting it or exporting a newly excluded category. A configuration change first stops the old sender and persists its memory stage. Bytes already submitted before that stop remain outside its control.

## What delivery status proves

A record is removed from the spool after a complete local UDP submission or TCP/TLS write. These are **local socket outcomes**, not collector processing receipts. UDP can lose datagrams; TCP/TLS can accept bytes locally that never become a complete receiver record. A partial write/disconnect can have an ambiguous result. A crash after a write but before removal, or a removal failure, can replay a duplicate. A crash after removal cannot recover data the collector had not processed. This is bounded durable retry until local submission, not exactly-once delivery or an end-to-end at-least-once application guarantee.

Health exposes:

- `queued`: all pending records; `durableQueued` and `spoolBytes`: committed backlog, including in-flight work; `memoryBytes`: memory-stage payload bytes. These are live observations and can move between fields during a concurrent read.
- `persisted`: newly committed records in this process; `replayed`: committed records loaded by this process (including paused loads), not proof they were sent.
- `writeAttempts`: connection/write attempts; `sent` and `sentBytes`: completed local submissions and payload bytes, including repeated submissions. `lastSentUtc` is local, not receiver time.
- `failed`: persistence/transport/start failures; `dropped`: full-queue, staging, expiry, corruption and binding discards. `expired` and `bindingDropped` identify subsets. Disabled/excluded events are not admitted and are not counted as queue drops.
- `oldestAgeSeconds`: age of the oldest committed pending record; `nextRetryUtc`: current head retry deadline; `lastError`: actionable degraded-state text. Counters and error history are process-local; spool contents/identities survive restart, counters do not. Concurrent fields are not an atomic accounting transaction; reconcile at quiescence.

`receiptSemantics` is always `NoApplicationReceipt`. Receiver readback in the local tests is separate out-of-band evidence; no receiver acknowledgment is implemented or inferred from TLS, a TCP write or the test API.

## Wazuh and backup boundaries

[Wazuh's remote configuration](https://documentation.wazuh.com/current/user-manual/reference/ossec-conf/remote.html) documents TCP/UDP syslog listeners and source allow-lists. It does not define an application receipt for this sender. Its secure agent connection must not be treated as native TLS syslog. A separately administered TLS syslog collector/relay may be needed for a Wazuh deployment. No live Wazuh instance was available or authorized here: Wazuh framing/decoder acceptance, ingestion, indexing, rules, receipt, relay behavior and deployment throughput remain unqualified. Generic loopback receiver success does not establish Wazuh acceptance.

Atomic per-node `syslog.json` stores configuration including a provisioned public CA locally. Payload spool files are plaintext under the existing configuration-folder access boundary; this change does not alter Windows ACLs or install certificates. Do not grant general access to that folder. New Unix record files use owner read/write only.

Native **Logging settings** backups include forwarding configuration with `Retain` in place of CA contents. They exclude CA bytes, private keys, pending spool records, checkpoints and counter history. Restoring custom trust requires that the destination already has its intended CA provisioned; a missing destination CA rejects the restore. Restoring settings applies a fresh revision and the same endpoint/trust/category binding rules to the destination's existing spool. It neither transports queued payloads nor recovers omitted work. Cluster transfers and new-deployment migration continue to preserve the destination's own forwarding configuration. Restoring older backups that contain a CA explicitly provisions that supplied public anchor under the existing administrator permission check.

## Local qualification

The focused syslog tests use only owned loopback receivers, ephemeral CA/leaf certificates and isolated configurations. They cover real UDP/TCP framing, Unicode/security-message bounds, native TLS readback, wrong CA/name/validity rejection, non-reading and partial receivers, capacity rejection, retained pause/drain/recovery, corruption/expiry/binding changes, native API current rights across waits, settings-only backup round trip, storage failure and a distinct full native application process restart. A checkpoint interruption after receiver observation demonstrates duplicate replay with original payload identity. Native authoritative NoError/AA/known-A responses and management responsiveness are checked during faults. Throughput reports finite offered/admitted/rejected/receiver-visible counts and measured monotonic windows; they are local observations, not production SLAs. DHCP packets/leases, host reboot/power-loss durability, other authorized network paths, system-PKI/revocation environments and live Wazuh remain untested. No UI change or screenshot claim is made.
