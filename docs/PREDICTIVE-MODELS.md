# Local advisory models

This increment provides an API workflow for local model mechanics. Empirical qualification is unavailable: no authorized representative labeled dataset was identified in the inspected accepted security documentation or configured environment reference names. That inspection does not establish that no authorized dataset exists elsewhere. Synthetic fixtures exercise implementation only. Neither a selected model nor held-out fixture counts establish detection accuracy, calibrated probability or production effectiveness.

Learned output is requested against retained security events. It has no connection to DNS decisions, shared device signals, DHCP, thresholds or recovery. The existing deterministic `heuristic-v2` score remains unchanged. Model operations use local CPU and files; they do not contact model servers, download models, transmit domains or collect live training traffic. The console is unchanged; these controls are API-only.

## Workflow and current permissions

All paths are under `/api/security/predictive/`. Existing session authentication applies. `list` and `context` require Settings View. `train`, `select` and `retire` require Settings Modify and Administration Modify, and must run on a cluster primary when clustered. Each predictive endpoint validates the admitted session against the live target session registry, current user object, disabled/expiry state and current permissions. Cached request admission alone conveys no continued authority. Form delivery is awaited explicitly, followed by renewed live authorization; write authorization is repeated before persistence and immediately before atomic publication after storage I/O. Checks do not refresh LastSeen and cannot revive an expired pending request. Registry/context reads also revalidate after form delivery and before disclosure. Sessions removed/replaced on the target, expired sessions and stale/deleted/disabled users are refused. The workflow requires a session still present in the target registry; a consumed single-use session cannot confer continued authority. Existing cluster acting-user mapping is retained, but its live session, current user/rights and primary-only write restrictions are checked; the cluster proxy/token matrix remains unqualified. No background training or delayed activation is scheduled. Model state is node-local and is not replicated with policy. Each write requires the current registry `revision`; a conflicting write fails without replacing current selection.

1. Read `list` to obtain the revision, selected and previous IDs, immutable artifacts, dataset receipts and explicit qualification status.
2. Prepare a locally authorized dataset before import. Record owner/source, license and permitted processing/derivative use, collection method/time, selection/exclusions, label meaning/origin and privacy basis in its provenance fields. Accessibility is not permission. Review representativeness, labeling and independent grouping separately. The product records these as operator assertions; it does not authenticate them or determine legal rights.
3. POST `train` with form fields `revision` and `dataset` containing the documented JSON structure. Training stores a receipt, learned parameters, baselines and held-out counts. It does not select the model. No raw dataset rows are retained by the registry; preserve the exact authorized input and split manifests separately under their approved retention controls.
4. POST `select` with `revision` and `modelId` to select an available unexpired version. Roll back by explicitly selecting the `previous` ID with the current revision. An empty `modelId` disables learned advice. Selection only affects subsequent advisory context requests; it does not activate protection.
5. Read `context` with `eventId` to inspect evidence time, source assertions, device context, the compatible feature vector and learned advice or fallback. Missing/evicted events return an error. All labels remain uncalibrated, with synthetic or supplied-sample limits attached.
6. POST `retire` with current `revision` and `modelId` to remove that version's stored learned parameters and baselines and clear selection/previous pointers that reference it. A tombstone prevents reimport of the exact dataset bytes. Reformatting bytes changes the hash: tombstones are an exact-input guard, not content-equivalence or legal withdrawal enforcement. Existing exports, external input copies, old backups and filesystem remnants are not recalled or securely erased. No model backup/export/restore API is added.

## Dataset and feature contract

`LearningDataset` fields are `source`, `license`, `permissionBasis`, `selection`, `labelProvenance`, `privacyBasis`, `collectedAt` (UTC), `synthetic`, `featureSchema`, `featureSourceSha256`, and `rows`. Source/provenance strings have a 1024-character limit. `featureSchema` must be `dns-domain-window-v1`. The feature source is the SHA256 of sorted normalized PSL rules, including wildcard/exception prefixes and a terminating LF. It identifies normalization semantics; the frozen source packet separately records the raw bundled PSL hash.

Each row contains `observationSha256`, `deviceGroupSha256` (lowercase SHA256), `observedAt` (UTC), `partition` (`Train` or `Evaluation`), `label` (`Benign` or `Suspicious`) and seven complete finite numeric `features`, plus optional `sampleLimited` (default false). Sample-limited training rows are rejected; sample-limited evaluation rows produce abstentions. Hashes and labels are supplied claims, not authenticated identities or ground truth. Unknown labels/missing values are rejected rather than counted as benign or imputed. Zero missingness in a receipt describes admitted rows, not completeness of the original population.

Features are fractions in [0,1], in this exact order: long-prefix-label observations, high-entropy-prefix observations, TXT observations, NXDOMAIN responses, distinct prefix fingerprints, DGA-lexical registered labels, and domain/hour sample count divided by 512. Definitions reuse the accepted analyzer's thresholds and PSL normalization. Samples are per client/domain within the rolling hour. A feature-definition SHA256 records this order, units, estimator, abstention and baseline mechanics. A different schema/order requires a new implementation/version; callers must not relabel arbitrary vectors with this schema. Feature-source mismatch produces fallback.

The intake accepts 60–10000 rows and requires at least 20 training and 10 evaluation rows for each label. Observation IDs cannot repeat. Training and evaluation device-group IDs must be disjoint, and every evaluation observation must be later than every training observation. No normalization, imputation, feature selection, threshold fitting or tuning uses evaluation rows. Exact partition hashes, row/group counts, observation bounds and training cutoff are retained. These mechanical checks do not detect dishonest hashes, repeated captures under different IDs, shared domain/source families or correlated windows. Before empirical work, freeze an independently reviewed grouping/time/label protocol covering those dependencies, any validation/tuning partition and final-test reuse. No empirical tuning or comparison protocol is claimed here.

The deterministic trainer learns the arithmetic seven-dimensional mean for each training label. Inference uses nearest-centroid root-mean-square distance. It abstains when nearest distance exceeds 0.35 or class-distance margin is below 0.05. Training class means separated by less than 0.05 are rejected as degenerate. These fixed engineering support bounds are uncalibrated and are not accuracy acceptance thresholds. Held-out evaluation uses the same observation-time, feature-source, model-time and distance/margin decision kernel as serving, at the recorded training-operation UTC `asOf`. Historical rows older than one hour at that instant abstain; the report is not a hypothetical historical replay or performance measured at future request times. Evaluation does not tune parameters or admit models based on performance. `served-advice-v2` records total/eligible rows, classified/abstained counts, abstentions by known label and reason, and coverage. The confusion matrix includes learned classifications only; deterministic fallback is neither benign nor a correct classification. Intake rejects unknown labels, so admitted `unknownLabels` is explicitly zero; unknowns are never silently counted as negatives. Precision is TP/(TP+FP), null without predicted positives. Recall among classified records is TP/(TP+FN), null without classified known positives. `knownSuspiciousDetectionFraction` is TP/(TP+FN+abstained suspicious); it is zero when every known suspicious row abstains, and null if the known-positive denominator is absent. Conditional precision/recall never stand in for coverage or full-cohort detection. No forced-label diagnostic is reported. All-abstaining reports show zero learned confusion counts, zero coverage, unavailable conditional precision/recall, and explicit fallback reasons. The updated feature-definition hash identifies these semantics; prior artifact protocols are incompatible and fall back until explicitly retrained under the new definition. Nullable arithmetic metrics are scoped solely to the supplied held-out cohort; no empirical accuracy, device-day exposure, delayed-detection, confidence interval or superiority claim is inferred from fixture counts. Representative data and an independently frozen empirical protocol remain gates.

Benign training groups with at least 20 distinct observation times over at least one hour receive a frozen mean baseline. Evaluation and inference never update it. Baselines expire for advice after seven days and are absent when identity is unknown, sparse or not in training. Baseline distance is descriptive drift, not a maliciousness probability or enforcement priority. Device grouping from event context includes scope, client identifier, hardware address, view, site and VLAN; it excludes an IP-only fallback. It is a pseudonym, not anonymity or authenticated identity. The resolver snapshot does not prove historical lease ownership. Changed attribution/context creates a different group.

## Time and source context

`context` distinguishes event observation time, earliest matching query in the bounded retained local event queue, model training time/cutoff, dataset collection time and baseline observation time. Earliest retained observation is not global first seen or domain registration age. Registration age stays unknown without a usable explicitly supplied registration-creation assertion.

An existing policy indicator may carry optional `provenance`: source record ID/revision, UTC observed/fetched/valid-from/valid-until times, `retracted`, optional `registrationCreatedAt`, and up to 32 typed IP/ASN/CNAME/Hosting assertions. The existing policy write validates bounded metadata and persists it with the indicator. Context reads evaluate both event-time availability and current expiry/retraction. Future, expired, malformed or retracted context is excluded from usable associations; future creation dates never become negative ages. Separate conflicting source assertions remain separate; the product does not choose a true owner. Shared hosting is not maliciousness evidence. Metadata is descriptive only and does not retract or alter the existing rule's configured action. Rule changes still require the existing policy workflow. No passive-DNS/registry/provider lookup is made. Context assertions never enter the learned features or historical predictions.

## Persistence, limits and fallback

The registry is `security-advisory-models.json`: bounded JSON data only, with no imported code, hooks, tools or server-selected file paths. It stores up to 16 versions, 1024 baseline groups per model, 128 exact-input retirement tombstones and a maximum 4 MiB envelope. One training operation per registry is admitted; concurrent training is rejected without queuing. The request is limited to 4 MiB. Operations are synchronous, bounded by row/dimension/count limits and perform no network I/O; no duration/SLA or process-wide management-request concurrency claim is made.

Writes flush a single `security-advisory-models.json.pending` file, recheck commit authorization and atomically replace the registry before publishing the in-memory revision. A revocation detected after pending-file I/O withholds publication and retains the bounded pending artifact under the same failure contract; already processed data are not retroactively recalled. Failed writes leave current state unchanged and retain at most one bounded pending artifact for operator inspection. Further writes fail while that artifact exists. Startup ignores pending work and never auto-trains/activates it. No automatic cleanup or recovery of pending work is implemented. An authorized operator must inspect and resolve that owned artifact before another write; this API has no arbitrary-file deletion control.

Dataset-byte, partition, feature-definition, model-artifact and outer payload hashes bind the local provenance chain and detect accidental changes. They do not authenticate a publisher or establish an authorized signature/trust chain. This is unsigned development scope. Changing source/preprocessing/PSL requires compatibility review and new artifacts. The loader rejects unsupported/malformed/oversize/numeric-incompatible or hash-invalid registries and exposes deterministic fallback; no model failure is in native startup's DNS path because the registry is loaded lazily by management requests.

Registry loading bounds both initial file length and actual bytes read to 4 MiB. Envelope/payload presence and integrity, null model entries, schema/parameter/receipt/selection references and numeric/time limits are validated before publishing state. Expected `InvalidDataException`, JSON decoding, filesystem I/O and access failures yield the explicit invalid-store fallback without overwriting failed bytes. Argument and null-reference exceptions are not broadly suppressed. This fixes a previously confirmed uncaught integrity-validation exception in lazy model-management reads; it does not establish that the prior version's native DNS startup failed.

Fallback retains the accepted deterministic heuristic with an explicit unavailable/reason state for missing, stale, corrupt, incompatible, sparse, sampled, future, ambiguous or unsupported data/models. Model lifetime is 30 days, and supplied data's latest observation must also be within 30 days. Event observations must be within one hour and contain at least 30 selected heuristic samples; truncated history is excluded. Baseline absence/staleness is separately reported because it is not a classifier feature. Rollback cannot resurrect retired artifacts or reinterpret incompatible features. Runtime store failures return an honest management error while the current selection remains usable. No license result, model or context can stop DNS/DHCP.
