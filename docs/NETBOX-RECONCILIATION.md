# Local NetBox reconciliation reviews

teQtanium remains authoritative for selected IPAM intent. This implementation prepares scheduled reviews, publishes explicitly reviewed local changes, reconciles individually selected managed deletions, and imports individually selected missing manual intent. It does **not** provide unattended publication, automatic deletion, automatic reverse synchronization, or remote authority modes. Import does not configure DNS, DHCP, interfaces or devices. Production activation and real endpoint compatibility require separate qualification.

## Scope and existing references

Enable the integration explicitly, select network views and existing VRFs (blank means the global table), object types, and optional subnet scope. Two local views cannot share one mapped VRF. An empty type selection produces an empty review; an empty subnet selection includes all subnets in mapped views. A removed scoped subnet remains eligible only through its explicit local deletion history, never through an incomplete remote page or mapping removal.

Optional per-prefix mappings select existing site, VLAN and tenant IDs. Site publication uses `scope_type=dcim.site` and `scope_id`, requiring NetBox 4.2+ prefix scope semantics. Optional address mappings select an existing device and its interface, using `assigned_object_type=dcim.interface` and `assigned_object_id`. The device itself is not edited. No DCIM object is created and no site/VLAN/tenant is inferred from a hostname, display label or observed device. Blank mappings preserve existing remote relationships; clearing or unlinking a relationship is not implemented.

Selected references must be readable at the configured target with the intended credential. Interface-to-device identity, explicit VLAN site/tenant relations and site-scoped VLAN groups are checked. Other scoped VLAN-group types are refused when a site mapping cannot qualify them. Selected device tenant relations are checked when supplied. Each referenced object's complete returned representation is fingerprinted in the review and re-read before effects; changed, inaccessible, deleted or reparented references invalidate approval. This can conservatively require a new review for an unrelated reference change. Arbitrary topology constraints, remote object ID reuse with indistinguishable representations and distributed remote transactions are not guaranteed.

References: [NetBox prefix scope](https://netbox.readthedocs.io/en/stable/models/ipam/prefix/), [IP address interface assignments](https://netbox.readthedocs.io/en/stable/models/ipam/ipaddress/), [DCIM interfaces](https://netbox.readthedocs.io/en/stable/models/dcim/interface/). Fixture success does not qualify a deployed NetBox version, schema or conditional-write implementation. Unsupported fields fail the operation; there is no silent schema downgrade.

## Scheduled reviews and lifecycle

Schedules are disabled by default and accept review mode only. Save an interval of 1–10080 minutes and a 1–60 second overall time limit. The server binds ownership to the authenticated saving user; a client-supplied actor is ignored. Every dispatch and delayed response checks that the owner still exists, is enabled, retains Administration and Settings Modify, and this service is standalone or cluster primary. A schedule may outlive its creator's login token, but never the creator's current account rights. No unrestricted system actor substitutes for missing rights.

The service checks due schedules every 30 seconds while running. UTC timestamps are persisted and displayed in the browser's named local timezone. Next due is admission time plus interval. Missed intervals coalesce into one current review, with no catch-up backlog. Existing settings, opening the console, upgrading, restoring integration settings or merely creating a view do not enable a schedule. Review generation has bounded 100 pages, 10000 objects per type and 8 MiB per response. Individual HTTP timeouts remain bounded; all direct publication/import/review operations also have a one-minute deadline.

The latest durable journal binds job ID, target/settings digest, local inventory revision, owner through the saved schedule, start/finish/due instants, preview ID, failure count and outcome. There is one latest review, one latest run and one latest publication result; generating a new review replaces only the review. Three failed reads or any conflicts suspend scheduling at Review needed. Explicitly resave the schedule to resume after examining the outcome. Cancellation acknowledges a request; reload status to see the saved Cancelled outcome. A failed terminal save shows Saving outcome, blocks new work, and retains the actual terminal result in memory. Authorized status reload retries storage only, preserving attempt identity and never replaying network I/O. If the process dies, the last disk Running marker becomes Interrupted and requires explicit schedule resumption.

An exclusive runtime file lease permits one connector/service per configuration. Origin-wide admission covers manual and scheduled review, publication and import, including different credentials, paths and mappings for the same normalized HTTPS origin. An exclusive temporary-file lease also serializes processes sharing the same host/temp namespace; process death releases that lease. DNS aliases, different reverse-proxy origins, separate temp namespaces, remote hosts and external NetBox writers cannot be proven to share a database. Use one canonical origin and one integration owner for a database. This is not distributed database locking or a guarantee of remote uniqueness against unrelated writers.

## Publication and deletion

Publication retains the existing review ID, settings hash, fifteen-minute expiry, exact local revision and installation ownership checks. Current authority and revision are rechecked after delayed I/O and before each effect. Updates/deletes require the reviewed remote timestamp, unchanged ownership and ETag/If-Match support. Creates recheck natural identity. Remote effects are not globally transactional. The result records acknowledged writes; an interrupted or lost response leaves an explicit unknown/partial result and the same preview cannot be submitted again, including after an actual process restart. A fresh review reconciles observed remote outcomes before any new approval.

Absence alone never authorizes deletion. A candidate requires a durable local subnet/assignment delete event containing its before-value, the one exact installation/type/local-ID marker, matching natural identity, current view/VRF mapping and current type/subnet scope. Objects with foreign, multiple, missing or conflicting markers, unknown local history, moved identity or an incomplete page are preserved. A normal review labels candidates Deletion needs approval. Individually select candidates and prepare a second review; only then can publication include their explicit Delete actions. The apply route additionally checks current Administration and Settings Delete for such actions. Removing a mapping never manufactures deletion intent. Deleting an address/prefix never requests deletion of its interface, device, VLAN, site or tenant. Remote dependency refusal remains a failed/partial outcome requiring reconciliation.

## Reverse proposals and local authority

Reverse review reads only mapped view/VRF and selected type/scope. It proposes missing prefixes or addresses in existing unlinked local leaf subnets. Existing intent, prefix overlaps, duplicate remote natural identities, mask differences, configured DHCP-linked subnets, DHCP/SLAAC statuses, and collected observation evidence are preserved. Missing masks, unsupported statuses and malformed/incomplete snapshots cannot establish static intent. Prefix containers remain containers. No service link is invented. Importing a missing prefix and its addresses is intentionally staged: import the prefix, refresh inventory, then prepare a new address review.

Select 1–100 proposals. Apply re-fetches each exact remote object and compares its full reviewed fingerprint, settings hash, expiry and local revision; current actor/primary rights are checked before the single local mutation. All selected objects validate together with current observations, usable boundaries, overlap, uniqueness and provisioning holds. Either all selected intent and the receipt persist atomically, or none do. Existing local fields are never overwritten. Receipts preserve selected external identities/revisions/values, review ID, target/settings digest, actor, timestamp and resulting local revision. A consumed review cannot duplicate intent after a retry/restart. Receipts are bounded at 1000 imports and fail clearly at capacity; preserve/archive history before further imports. Ordinary Settings readers receive the resulting local inventory, not private NetBox review receipts or hidden import IDs.

## API and operator access

All integration routes require current Administration and Settings Modify and primary/standalone ownership. Deletion previews and delete-containing applies also require Delete in both sections. Shared latest reviews are available to other currently authorized integration administrators; a preview ID grants no rights. The console clears settings, previews, selections, hidden review IDs, drafts and outcomes on logout, actor change or a new token, and suppresses stale success/error/invalid-token callbacks.

Existing routes are `settings/get`, `settings/set`, `preview`, `apply` under `/api/ipam/netbox/`. Added routes are `preview/get`, `deletions/preview`, `import/preview`, `import/apply`, `schedule/set`, `schedule/run`, and `schedule/cancel`. Mutations use POST. `preview/get` and `settings/get` also support GET. Selection is an explicit comma-separated key list such as `prefixes:123`; the server re-derives eligibility. Settings use credential environment references, never stored keys. Backup preserves integration settings and installation identity, excluding secrets and schedules; restored schedules are not implicitly authorized.

## Qualification boundary

`dotnet tests/Ipam.Tests/bin/Release/net10.0/Ipam.Tests.dll --netbox-reconciliation` exercises disposable pinned loopback TLS, native APIs/model persistence, current permissions/primary transitions, reference drift, conditional deletion, individual atomic reverse import, overlap, deadlines, failed saves, bounded retries and actual killed-process recovery before/after a remote effect. Inherited NetBox, IPAM, provisioning and discovery regressions remain applicable. `--serve` is a test-only disposable UI harness with private generated credentials; never use it as a production configuration or publish its session/evidence files.

Local native/UI verification and source/build freezing are inputs to independent acceptance. They do not qualify live NetBox activation, endpoint/version/ETag support, live client continuity, multi-host/distributed exclusion, arbitrary remote aliases, real device configuration or production availability. No live external inventory mutation or production deployment is part of this implementation.
